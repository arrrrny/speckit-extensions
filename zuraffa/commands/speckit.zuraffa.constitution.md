# Zuraffa Constitution

Add the zuraffa framework principles to `.specify/memory/constitution.md`. These
are NON NEGOTIABLE and trace directly to the [VISION](https://github.com/arrrrny/zuraffa/blob/master/VISION.md).
The punchline that frames all of them:

> **Zuraffa's superpower isn't generating code. It's generating proof.**
> Stochastic mind, deterministic hands.

## The Principles

Append the following section to the constitution (create the file if absent).
If a principle already exists in a different wording, replace it with this
wording — the constitution is the single source.

```markdown
## Zuraffa Framework Principles (NON NEGOTIABLE)

Inherited from the zuraffa VISION. Violating any of these invalidates the feature.

### 1. Intent is the source code. Dart is the assembly. (VISION §1)

The spec — authored from the zuraffa template — is the only source of truth.
`zfa` compiles intent into architecture. Code stops being authored and becomes
a build artifact: regenerable dust. Drift is physically impossible because
there is nothing to drift from. Never hand-edit generated files
(`.zorphy.dart`, `.g.dart`, zfa scaffolds); regenerate via `zfa build`.

### 2. The framework is the referee, not the assistant. (VISION §2)

Failing tests are generated FIRST. Implementation is refused until RED is
verified. Green happens only on proof. An agent that hallucinates doesn't ship
broken code — it cannot pass physics. Never ease a gate, never fake evidence,
never mark work done while the suite is red. A green suite built on a
workaround means nothing.

### 3. The manifest is a treaty. (VISION §3)

The machine-readable contract between the CLI and every agent is sacred.
Contract drift (help-text, flags, behavior deviating from the manifest) fails
the build. For an agent, a wrong flag isn't a typo — it's a hallucination
factory.

### 4. Errors are an API, not an apology. (VISION §4)

Exit codes are a protocol: 0 success, 1 RED, 2 grammar, 3 contract drift,
4 state conflict. Every error message ends with a machine-actionable
`--> fix:` line. Exit-0-on-error is heresy: one silent lie poisons the agent's
entire belief state. In Dart code, UseCases return
`Future<Result<T, AppFailure>>` — raw throws from use cases are forbidden.

### 5. Token economics are a design constraint. (VISION §5)

Prefer `--json` verdicts, diff-summaries, and NDJSON streams over log walls.
Five lines that decide the next action beat two thousand lines of output. A
tool that respects context windows is a tool agents prefer.

### 6. The repo is the agent's long-term memory. (VISION §6)

Baselines, golden files, cycle-logs, run-state, spec history, decision records
— all committed, all institutional memory. An agent joining fresh doesn't read
code to understand the system; it reads the intent layer. Never hand-edit
run-state, artifacts, or cycle-log: recovery goes through system commands
(`zfa tdd reset`, `--adopt`, `doctor`).

### 7. Humans review diffs of intent, not boilerplate. (VISION §7)

Specs are the interface between agents; the CLI referees every round with
deterministic verdicts. Code review becomes philosophy review: review the
spec change, not the generated implementation of it.

### 8. The codebase is self-healing. (VISION §8)

`zfa doctor` diagnoses rot, applies migrations, re-syncs artifacts. Upgrade
the framework → regenerate → the diff shows only intent changes. The codebase
is a crystal that re-forms around the spec, not a garden that needs weeding.

### 9. Simulation worlds come before production truth. (VISION §9)

Every external dependency gets a mock the FRAMEWORK certifies — never mocks
the agent wrote (that's grading your own homework). `zfa mock create`
generates contract-conforming mocks from declared Dependencies & Contracts;
real adapters must satisfy the same contracts or the suite fails. Ship
against simulated reality first; earn production truth through the realize
ladder.

### 10. Clean Architecture layers are physics, not preference.

Domain has zero imports from data or presentation. Data implements domain
interfaces. Presentation consumes domain through use cases only. Entities are
Zorphy (`@Zorphy(generateJson: true)`, typed copyWith). All architecture is
generated by zfa commands — if zfa cannot generate it, that's a zfa issue to
file, not a license to hand-roll.
```
